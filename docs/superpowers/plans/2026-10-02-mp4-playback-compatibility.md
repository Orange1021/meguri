# MP4 Playback Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatically transcode MP4-family videos whose indexed codec cannot reliably produce Chromium video frames, while preserving native H.264 playback and showing a clear error for unknown no-frame cases.

**Architecture:** Add a small media-routing query that supplies the server with the indexed file kind, codec, and ffprobe metadata. Extend the existing remux session with an explicit forced-transcode mode and route non-baseline MP4-family video through it; add a renderer-side no-frame guard as defense in depth. Keep the portable `Data` directory outside the change set.

**Tech Stack:** Electron 42, TypeScript, better-sqlite3, Node HTTP Range server, ffmpeg, Vitest, Playwright, electron-builder.

### Task 2: Implement codec-aware media routing

**Files:**
- Modify: `electron/core/tags.ts`
- Modify: `electron/core/server.ts`
- Create: `electron/core/mediaPlayback.ts`
- Test: `electron/core/__tests__/server.test.ts`
- Test: `electron/core/__tests__/mediaPlayback.test.ts`

- [ ] **Step 1: Define the routing policy with unit tests.**

Add pure helpers that recognize MP4/M4V/MOV, treat H.264 with `yuv420p` as raw-playable, and request transcoding for non-H.264 or non-baseline pixel formats only when the file kind is video and the codec is known. Cover `mpeg4`, `hevc`, `h264`/`yuv420p`, `h264`/`yuv420p10le`, audio rows, and unknown metadata.

- [ ] **Step 2: Add one database lookup for media playback metadata.**

Return `absPath`, `kind`, `codec`, and parsed `meta` from one live-file query. Preserve `absPathOf` for its existing IPC callers.

- [ ] **Step 3: Add forced-transcode mode to the existing remux session.**

Make the remux key include the mode, accept a `forceTranscode` flag, and start directly with the existing H.264/AAC fragmented-MP4 arguments when the flag is set. Keep copy-first/fallback behavior unchanged for legacy containers.

- [ ] **Step 4: Route non-baseline MP4-family video through forced transcode.**

Use the new media metadata and policy before the raw `serveFile` branch. Honor `?t` in the same branch so stream seeks remain relative to the requested second.

- [ ] **Step 5: Run the targeted server and policy tests.**

Expected: the new MPEG-4 test and all existing server tests pass, with the response probe proving H.264/AAC rather than only checking the `ftyp` header.
