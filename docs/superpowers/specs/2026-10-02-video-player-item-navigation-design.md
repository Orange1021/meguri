# 视频播放器控制与显示模式设计

## 目标

本次调整包含三个相互关联的播放器体验改进：将详情页视频播放器底部现有的“后退 10 秒”和“前进 10 秒”按钮改为“上一个视频”和“下一个视频”；移除详情页顶部重复的上一项/下一项按钮；增加按视频保存的画面显示模式；并让全屏只覆盖视频播放器本身。

## 用户行为

- 播放器底部左按钮切换到当前导航上下文中的上一个视频。
- 播放器底部右按钮切换到当前导航上下文中的下一个视频。
- 当前已经是第一个或最后一个视频时，对应按钮不可用，不循环到另一端。
- 从普通列表打开详情时，使用普通列表的顺序。
- 从全屏播放列表进入详情时，使用该播放列表的播放顺序。
- 键盘左右方向键以及 `J`/`L` 的视频内快退/快进行为保持不变。
- 全屏播放列表自己的控制条已经提供上一项/下一项按钮，本次不改变它。
- 每个视频单独保存自己的画面显示模式，切换到其他视频时使用其他视频已经保存的模式。
- 新视频默认使用“适应窗口”模式。
- “适应窗口”完整显示视频并保持比例，可能留下黑边。
- “铺满窗口”保持比例并填满播放器，必要时裁掉边缘。
- “拉伸填满”不保持比例，直接把视频拉伸到播放器大小。
- 画面模式通过播放器底部的显示模式菜单选择。
- 点击全屏后，只有视频播放器及其控制栏进入浏览器全屏；标题、标签、详情和外层滚动区域不进入全屏。

## 实现边界

### 详情页播放器

为 `VideoPlayer` 增加可选的上一项/下一项回调及可用状态。底部两个控制按钮调用这些回调，使用现有的 `media.prev` 和 `media.next` 本地化文案，并在没有目标视频时禁用。

### 详情页导航

`MediaDetail` 将现有 `usePrevNextNavigation` 返回的 `goPrev`、`goNext`、`canPrev`、`canNext` 传给 `VideoPlayer`。这样普通列表和从播放列表进入详情的上下文选择继续由现有导航 Hook 负责。

### 顶部导航

`TopBar` 删除上一项/下一项按钮及其相关参数；保留标题、关闭、播放列表入口、窗口尺寸和展示模式等其他操作。`usePrevNextNavigation` 仍然保留，因为它继续负责底部按钮和键盘快捷键。

### 画面显示模式

`VideoPlayer` 使用一个按工作区和文件 ID 索引的本地存储映射保存模式，避免不同视频之间相互覆盖。播放器通过 `object-contain`、`object-cover` 和 `object-fill` 分别实现三种显示模式；模式菜单使用现有的下拉菜单组件，并显示当前模式。

### 真正的播放器全屏

播放器自己的外层元素成为 Fullscreen API 的目标，不再把详情页 `MediaModal` 作为全屏目标。详情页不再根据整个模态框的全屏状态隐藏标题或改变滚动布局；浏览器只呈现播放器元素及其子元素，从而不会出现全屏后还能向下滚动详情内容的问题。

## 测试

- 视频播放器组件测试底部按钮分别调用上一项和下一项回调。
- 测试边界状态会禁用对应按钮。
- 详情页导航测试改为通过播放器底部按钮验证普通列表和播放列表来源的切换。
- 测试三个画面模式的 CSS 映射、按视频保存和新视频的默认模式。
- 测试全屏请求的目标是播放器元素而不是详情模态框。
- 回归验证键盘快退/快进和全屏播放列表控制条不受影响。

## 验收标准

1. 详情页顶部不再显示重复的“上一个文件/下一个文件”按钮。
2. 鼠标移到视频底部控制栏后，左右按钮显示并执行上一个/下一个视频切换。
3. 点击这两个按钮不会再改变当前视频的播放时间。
4. 键盘快退/快进仍然可用。
5. 普通列表和播放列表来源都沿用原有正确顺序。
6. 不同视频可以分别保存不同的画面显示模式。
7. 全屏状态下详情页其他内容不可见且不能滚动。
