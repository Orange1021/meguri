# 橙映（OrangeView）便携布局、诊断与品牌统一设计

## 目标

本轮把阶段二的基础设施收口，覆盖五个用户可见问题：

1. 侧边播放区固定在左侧，All、Video、Image 以及其他列表视图统一把列表留在右侧。
2. 数据库、缩略图、配置、播放列表和日志都位于便携根目录的 `Data/` 或 `Media/` 下，复制完整目录后保持同一份数据。
3. 扫描与缩略图失败同时保留主日志和结构化扫描问题，界面显示失败原因并提供打开日志目录的入口。
4. 软件对外名称改为“橙映”，内部包名、协议和旧数据键保持兼容。
5. 橙色 Logo 作为唯一品牌资源，统一用于应用内、窗口/任务栏、托盘和安装包资源。

## 设计决策

### 布局

Home 的列表行按“播放区 → 列表 → 选择层”排列。`MediaModal` 的 peek 面板使用右边框和右侧拖拽手柄，宽度拖拽方向与视觉边缘一致；键盘方向键也改为右键增宽、左键减宽。普通 modal 不改变。

播放区位于左侧后，右下角播放/发现按钮不再为右侧 peek 预留空白，避免按钮被不必要地向左挤压。

### 便携根目录

便携启动器既支持约定的 `Root/App/OrangeView.exe`，也支持把单个便携可执行文件直接放在 `Root/` 运行：

```text
Root/
  App/                 # 安装包应用文件（可选）
  Data/                # SQLite、配置、缩略图、播放列表、日志
  Media/               # 用户媒体根目录（可选）
```

启动器被复制到移动硬盘时，必须复制整个 `Root/`，而不是只复制 `App/` 或单个 exe。媒体若也位于 `Media/` 内，数据库中的相对工作区定位和媒体结果会随目录一起保持；外部绝对路径媒体需要在新磁盘重新注册。

### 诊断

- 主进程和渲染进程日志继续写入 `Data/logs/main.log`，并自动轮转 `main.old.log`。
- `ScanManager` 的失败事件携带有限长度的原始错误详情和日志路径。
- ffprobe、ffmpeg 缩略图失败写入 `scan_issues`，与扫描运行记录关联，保留文件 ID、阶段和详细原因。
- 设置 → 应用提供“打开日志目录”，用户无需手工寻找数据目录。

### 品牌

可见名称统一为“橙映”，Windows 可执行文件使用 ASCII 名 `OrangeView.exe`，以减少移动硬盘、脚本和外部工具对 Unicode 文件名的兼容风险。`meguri` 包名、URL scheme、localStorage 键和历史文档中的内部兼容标识不在本轮删除。
Electron 的内部数据命名空间和 Windows AppX application id 继续保留旧值，避免已安装版本和旧用户数据目录失去升级关联。

Logo 只从共享橙色资源派生；主窗口、托盘、macOS Dock、Windows 静态资源和 appx 资源都必须继续使用同一资源。

## 验收标准

- renderer 单元测试能验证 peek 的右边缘拖拽/键盘方向；Playwright 能验证面板实际位于列表左侧。
- portable path 测试覆盖 `Root/App` 和直接 `Root` 两种启动位置。
- scan manager 测试验证失败事件含错误详情和日志路径；jobs 测试验证缩略图失败写入 `scan_issues`。
- typecheck、核心测试、renderer 测试、Playwright、构建和 portable 安装包均通过。
- 运行时和打包后的所有应用图标入口仍指向橙色 Logo；不引入旧 logo 资源引用。
