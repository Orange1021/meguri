# 仅视频生成索引图设计

## 背景

当前扫描管线会为受支持的图片文件调用 FFmpeg 生成缩略图。图片本身已经是可直接查看的原始画面，用户希望图片仍然出现在文件列表中并可点击打开，但不再额外生成图片缩略图。视频文件继续生成索引图；Java、C++ 等不支持的非媒体文件继续被扫描器忽略。

## 目标

1. 只有 `video` 类型文件生成 `files.thumb_path` 索引图。
2. `image` 类型文件仍然完成索引、元数据提取、搜索和原图打开，但缩略图状态为 `done` 且 `thumb_path` 为 `NULL`。
3. `audio` 类型文件不再因内嵌封面生成索引图；已有音频缩略图引用在扫描时清理。
4. 既有图片/音频缩略图引用和当前 `Data\\...\\thumbs\\<id>.webp` 缓存文件在下次扫描时清理；只删除应用生成的缓存，不触碰用户原始文件。
5. 图片与音频不再创建自动 Cover/Sheet 派生任务；数据库中遗留的非视频任务直接完成而不调用 FFmpeg。
6. 视频现有缩略图生成、封面和联系表行为不变。

## 设计

### 扫描与缩略图策略

扫描器仍然只把 `kindForExt` 能识别的媒体写入数据库，非媒体扩展名不进入索引。`runScan` 继续为图片提取尺寸等元数据，但在缩略图阶段直接记录 `skipThumb`，不调用 `generateThumb`，并把图片设为 `thumb_status='done', thumb_path=NULL`。视频保持原有 FFmpeg 流程；音频仍可提取播放元数据，但不再提取封面。

扫描开始后，清理当前根目录中所有非视频的 `thumb_path`。只有路径严格位于当前 `thumbs` 目录且文件名等于 `<id>.webp` 时才删除物理缓存；数据库引用无论旧路径是否仍存在都会被清除。

### 派生资产任务

`queueDerivedAssets` 只为视频排队自动 Cover 和 Sheet。`processPendingAssetTasks` 对历史遗留的图片/音频任务直接标记完成，`generateTask` 在检查到非视频文件时立即返回，保证升级旧数据库时不会生成新图片。

### 用户体验

图片卡片仍然由现有文件列表和链接渲染，点击路径不变。由于不再有 `thumb_path`，图片卡片显示现有的图片类型图标；视频卡片继续显示索引图、播放按钮和悬停预览。

## 验证

- `runScan` 测试证明图片不调用 `generateThumb`，仍写入文件行、指纹和元数据，并最终是 `done/NULL`。
- 清理测试证明旧图片缩略图引用和当前 Data 缓存会被清除，而原始图片仍存在。
- `queueDerivedAssets` 测试证明只有视频创建 Cover/Sheet 任务。
- 遗留非视频 asset task 测试证明任务完成且不会调用 FFmpeg。
- 运行核心/渲染/便携升级全套测试、类型检查、便携版构建和启动验证；数据目录不进入 Git。
