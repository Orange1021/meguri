# 中文用户体验与橙子品牌设计说明

- 日期：2026-10-02
- 状态：待用户评审
- 分支：`feat/portable-video-library-v2`
- 范围：中文用户手册、简体中文默认界面、橙子圆形图标

## 1. 背景与目标

当前 Meguri 已具备本地媒体扫描、浏览、搜索、播放、标签、收藏、集合、播放列表、历史记录以及便携式数据目录等能力，但新用户仍需要从英文网页或代码上下文中理解使用方式。同时，应用内还保留了原有的“巡”字图标及三种旧 Logo 变体。

本次工作面向中文 Windows 用户，完成三个相互关联的体验改进：

1. 提供一份与当前实际功能一致的简体中文用户手册，让用户知道如何首次配置、浏览媒体、管理元数据、备份和排障。
2. 新安装或没有语言偏好的用户默认进入简体中文；已选择其他语言的用户继续保留原有选择，并可在设置中切换。
3. 用统一的橙色圆形水果图标替换应用窗口、托盘和应用内工作区栏中的旧 Logo，并兼容已有配置文件中的旧 Logo 值。

本次不改变媒体文件、数据库实体模型、扫描规则或播放协议；重点是可理解性、品牌一致性和向后兼容。

## 2. 用户手册

### 2.1 交付位置

新增 `docs/user-guide-zh-CN.md` 作为中文用户手册的单一维护入口，并从根目录 `README.md` 和文档入口页提供明显链接。现有英文 `docs/guide.html` 保留，不在本次工作中删除或改写为中文，以避免破坏已有外部链接。

### 2.2 内容范围

手册必须以普通用户能够照着操作为标准，至少覆盖：

- Windows 便携版的启动、首次运行和退出方式。
- 添加媒体文件夹、递归扫描、扫描进度以及重新扫描。
- 网格/列表浏览、搜索、筛选、排序和跨工作区浏览。
- 打开详情、播放视频、图片查看、播放进度恢复、全屏和常用快捷键。
- 收藏、评分、标签、场景书签、播放历史和稍后观看。
- 普通集合、智能集合、播放列表、M3U8/外部播放器相关入口（仅描述当前已经存在的能力）。
- 缩略图/封面/Sheet 等资源的来源和失败时的处理方式，避免用户误以为应用会修改原媒体。
- 主题、界面语言、缩放、音频可视化等设置的位置和作用。
- 便携式目录结构：`App`、`Data`、`Media` 的职责，配置、数据库、缩略图、日志和备份的去向。
- 备份、恢复、升级失败时的安全操作和 Windows 排障清单。
- 隐私边界：应用读取用户选定的媒体目录，应用自身数据与媒体分离；不应声称不存在代码实际支持的网络行为。

描述功能时以当前界面和 IPC 能力为准；如果某项能力有平台差异、需要手动启用或仍处于实验状态，必须明确标注前置条件。文档应使用短步骤、表格和 FAQ，避免只列内部模块名称。

## 3. 简体中文默认界面

### 3.1 语言选择规则

保留现有 `meguri.lang` localStorage 偏好和设置页语言切换：

1. 如果 `meguri.lang` 是支持的语言 ID，继续使用该语言。
2. 如果没有偏好、偏好值无效或 localStorage 不可用，使用 `zh-CN`。
3. `LANGUAGES` 将简体中文放在首位；其他语言仍然可选。
4. 更新 `<html lang>` 和偏好持久化的现有逻辑，不新增第二套语言状态。

### 3.2 品牌文本

`app.name` 在所有语言目录中统一为 `Meguri`，不再把“巡”作为应用显示名。这样可以同时满足中文界面、跨语言品牌一致性和 Logo 替换，避免设置页、关于页或回退翻译重新显示旧品牌字样。其他翻译只在确有必要时调整，避免无关的整套重译。

### 3.3 可理解性验收

- 中文默认启动后，首页、工作区栏、设置、详情、播放和错误提示等可见文本必须优先命中 `zh-CN` 目录。
- 保持现有 locale key 集合校验；不能通过删除 key 或让大量文本回退到日文来“通过”测试。
- 语言切换后仍能实时更新界面，刷新后继续保持用户选择。
- 无效或损坏的语言偏好不能导致白屏、未定义文本或无法打开设置。

## 4. 橙子圆形 Logo

### 4.1 视觉方向

采用已确认的方案 A：一个明亮的橙色圆形水果主体，带轻微高光、切面/纹理暗示和绿色叶片，外形在 16px 托盘图标、50px 工作区栏和窗口图标中都能识别。图标使用代码原生 SVG 作为主源，避免依赖字体、中文字符或操作系统字体差异。

设计约束：

- 主体为近似圆形，轮廓简洁，缩小时仍保留“橙子”语义。
- 橙色使用足够的明暗层次；叶片使用低饱和绿色作为识别点。
- 不再包含“巡”字、圆相笔刷或旧深浅色背景变体。
- 在深色和浅色主题、窗口、托盘和应用内工作区栏上均保持可读。
- SVG 的 viewBox、尺寸和颜色常量集中维护；渲染端和主进程不得各自绘制两套不一致的图形。

### 4.2 运行时与配置兼容

- 新的规范 Logo ID 为 `orange`，作为唯一可见和可写入的 Logo 选项。
- `DEFAULT_LOGO` 改为 `orange`；新配置和设置页只使用该值。
- 读取旧版 `config.json` 时，`dark`、`light`、`enso` 以及未知值统一归一到 `orange`，并按现有安全配置写回流程保存规范值。
- `logo_get`/`logo_set` 的 IPC 类型保持边界校验；不允许 renderer 传入旧值继续选择旧资产。
- 设置页保留“应用图标”说明和图标预览，但移除三种旧 Logo 选择器；预览明确标注“橙子”，该区域改为只读品牌说明。
- 窗口、托盘、macOS Dock（如适用）以及工作区栏使用同一套橙子资产。旧的 `logo_set` IPC 仍保留边界校验和向后兼容，但唯一允许写入的值是 `orange`，不能回退到旧 PNG。

### 4.3 静态资产

为应用内运行时保留一份可审查的 SVG 源文件，并同步更新文档站点使用的 Logo。Electron 主进程所需的 native image 应从同一源生成或转换；不能继续依赖包含旧字形的三组 base64 常量。打包图标在本次实现中应同步到橙子版本；如果某个平台的二进制图标转换工具不可用，必须在验收记录中明确说明，而不是宣称所有发行物图标已经更新。

## 5. 影响范围

预期触及以下边界，禁止扩散到媒体领域模型：

- `src/i18n/I18nProvider.tsx` 与各语言目录的品牌文案。
- 设置页、工作区栏以及 Logo hook/资产引用。
- `shared/ipc/schema.ts` 的 Logo ID 和 `electron/core/appConfig.ts` 的兼容解析。
- `electron/core/logoAssets.ts`、窗口/托盘图标应用逻辑及打包/文档图标。
- `README.md`、文档入口和新增中文用户手册。
- 对应的 renderer、core、配置迁移兼容和资源渲染测试。

不修改：媒体文件内容、扫描身份算法、SQLite 表结构、播放协议、已有工作区路径语义和便携式升级流程。

## 6. 验收标准

### 功能

- 清空语言偏好后启动应用，默认 UI 为简体中文；切换到其他语言、重载应用后选择仍保持。
- 使用包含旧 Logo 值的配置启动，应用成功启动、所有图标显示橙子，配置不会继续产生旧 Logo 值。
- 新配置、窗口图标、托盘图标、工作区栏和设置预览均使用橙子资产；渲染和主进程不再导入旧 Logo 资产，旧 ID 只能作为配置迁移输入保留。
- 中文手册可以从 README 和文档入口访问，内容与当前功能和便携目录一致。

### 工程质量

- 新增或调整测试覆盖默认语言、语言持久化、Logo 旧值归一化、唯一 Logo 选择、资源渲染和文档链接。
- 通过 typecheck、相关 lint、core/renderer 回归测试以及可执行的 E2E/Windows 打包验证。
- 不能把已有全仓 lint 基线问题误报为本次修复；验收报告需区分本次改动结果和既有问题。
- 在 Windows portable 目录中至少完成一次启动、设置打开、添加媒体目录、重启和托盘/窗口图标检查。

## 7. 非目标与后续工作

本次不实现完整的多语言重译、不删除已有英文在线指南、不改变数据库 schema、不重做播放器、不引入云同步，也不把 Logo 设计扩展为主题系统。后续如果需要正式的品牌资源包，可在本说明验收后单独补充各平台 ICO/ICNS 多尺寸导出规范和品牌色 token。
