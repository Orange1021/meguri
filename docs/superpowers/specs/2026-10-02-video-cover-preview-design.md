# 视频封面预览设计

## 背景

当前媒体列表中的视频条目本身就是播放入口：用户点击封面、文件名或条目其他区域时，会沿用现有行为进入视频播放流程。视频已经支持手动设置主封面，但用户只能在条目缩略图中看到封面，无法在不播放视频的情况下查看较大的封面图。

## 目标

在视频列表条目的封面右上角增加一个独立的“查看封面”按钮。用户点击该按钮时查看封面大图，点击条目的其他区域时保持原来的播放行为不变。

## 用户交互

1. 只有视频且已经存在可用主封面时显示按钮；封面仍在生成、生成失败或没有封面的条目不显示该按钮。
2. 按钮位于封面右上角，使用眼睛图标、半透明深色背景和“查看封面”无障碍标签/悬浮提示。
3. 按钮是独立的交互目标。点击时阻止默认链接行为和事件冒泡，因此不会同时触发整行或缩略图的播放。
4. 点击按钮打开居中的封面预览对话框；对话框只显示封面图片，不加载或启动视频。
5. 对话框使用 `contain` 方式显示完整封面，支持现有 Dialog 的关闭按钮、Esc 和点击遮罩关闭，并显示文件名作为标题。
6. 封面请求失败时，对话框显示明确的失败提示而不是空白或永远加载；关闭后可以再次打开重试。
7. 封面 URL继续使用当前的缩略图版本号，手动设置封面或后台重新生成封面后不会长期显示浏览器缓存中的旧图。
8. 封面预览支持独立缩放和平移：按住 `Ctrl` 滚轮缩放，放大后按住鼠标左键拖动查看其他区域；平移受预览窗口边界限制，缩回 `1` 倍后自动居中。
9. 预览窗口获得焦点后支持 `+` / `-` / `0` 缩放和方向键平移；指针捕获取消或丢失时清理拖动状态，不留下“抓取中”的交互状态。

## 范围与不变项

- 本次入口落在垂直媒体列表的行缩略图上，先解决用户当前使用的“每个视频一行”的场景。
- 不新增播放按钮，不改变列表原有的播放/详情跳转逻辑。
- 不在播放器控制栏、详情页主播放器或图片条目上新增同名按钮。
- 不生成新的图片文件；预览直接读取当前主封面缩略图。

## 组件边界

- `CoverPreviewButton` 只负责图标按钮的视觉、无障碍标签和阻止冒泡，不负责决定预览内容。
- `CoverPreviewDialog` 是受控的展示组件，接收 `open`、`onOpenChange`、封面 URL 和文件名；它负责图片加载失败状态、Dialog 生命周期、临时缩放状态和边界内平移状态。缩放和平移只在当前预览会话中生效，不写入用户偏好。
- `MediaList` 在列表层保存当前预览项，并根据视频行的 `hasThumb`、文件 ID 和版本号计算封面 URL；`MediaRow` 只把按钮放在缩略图容器上。

## 可验证标准

- 具有封面的视频行显示“查看封面”按钮；音频、图片、无封面视频不显示。
- 点击按钮后能看到 Dialog、文件名和对应的封面 URL；父级播放链接不会被触发。
- 点击关闭按钮、遮罩或按 Esc 后 Dialog 消失。
- 封面 `<img>` 触发 error 后显示失败提示，再次打开时会清除上一次错误状态。
- 放大后鼠标拖动会移动封面但不会把图片完全拖出视口；按 `pointerup`、`pointercancel` 或 `lostpointercapture` 后可以再次开始拖动。
- 缩回 `1` 倍会清除平移偏移；聚焦预览窗口后，键盘缩放和方向键平移可用。
- 既有 MediaList、缩略图、播放器和完整测试继续通过。
